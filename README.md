# PantryChef — snap your food, get a recipe

Mobile-first web app. Point your camera at the food on your counter, take a
photo, and get recipes that use exactly what you have.

## How it works (two models, two jobs)

1. **Photo → ingredients** — a vision model (`gpt-4o-mini` via OpenRouter) looks
   at the photo and lists the food it sees.
2. **Ingredients → recipes** — DeepSeek V4 Flash generates recipes constrained to
   only those ingredients (the cheap, fast text model).

The API key never lives in this repo or in the browser — it's a Modal Secret on
the backend. This frontend is a static GitHub Pages app that calls the backend.

- Backend: `https://ramtheham--pantrychef-analyze.modal.run` (POST JSON `{images: <dataURL[]>, assume_basics: <boolean>, profile: <taste summary>}`)
- Health: `https://ramtheham--pantrychef-health.modal.run`

## Run the frontend

Open `index.html` directly, or serve it. There's no build step. It compresses
the photo client-side before upload.

## MVP scope (honest)

This is an MVP demo. The photo analysis is a real vision model, but the recipe
output is generated by an LLM from the ingredients it sees — not a chef, not a
nutrition database. Label shown on every screen. No accounts, no tracking.


## End-to-end checks

Node 22.12+ and Python 3 are required for the test runner and local static server.

```sh
npm ci
npx playwright install chromium --with-deps
npm run check
npm run test:e2e
```

The suite uses the real [tester-army/e2e](https://github.com/tester-army/e2e)
runner, pinned to `e2e@0.16.0`, `@e2e-dev/web@0.11.2`, and
`playwright@1.63.0`. Tests drive browser uploads, compression, recipes, ratings,
settings, and failure recovery at 390px. Backend calls are intercepted with
synthetic responses: no model key, live AI calls, or production writes are
needed. Reports, traces, and JUnit results are written to `.e2e/`.
See [the flow matrix](docs/E2E_AUDIT.md) for the precise coverage and limits.

For an existing Chromium CDP endpoint, set `E2E_CDP_ENDPOINT` before running
the suite. The endpoint must be reachable from the same network environment as
the runner. Otherwise the engine launches the installed Playwright Chromium.
